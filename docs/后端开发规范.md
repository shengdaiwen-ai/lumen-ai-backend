# Lumen AI 服务端开发规范

> 适用仓库：`lumen-ai-backend`（Spring Boot 服务端）
> 版本：v1.0 · 最后更新：2026-09-17
> 定位：**可执行的规则**，不是宣传材料。每条规则都对应本项目里真实踩过的坑。

---

## 0. 红线清单（动手前先读这 13 条）

违反下面任意一条，代码一律不合并。

> 12 条编号红线 + 1 条关于基础设施地址的补充（1b），共 13 条禁止项。

| # | 红线 | 为什么 |
|---|---|---|
| 1 | **源码中禁止出现任何明文凭据** | 本仓库是**公开仓库**。真实值只能放 `application-local.yml`（已 gitignore）或环境变量 |
| 1b | **禁止在代码、注释、文档里写真实基础设施地址**（生产 IP、域名、库名、账号） | 同为公开仓库。示例一律用 `<DB_HOST>` / `example.com` 这类占位符 |
| 2 | **禁止新增 Mapper XML** | 全项目零 XML，一律用 MyBatis-Plus 的 `LambdaQueryWrapper`。混用会破坏一致性 |
| 3 | **禁止在 `@RestController` 里写业务逻辑** | 控制器只做参数接收 + 调 Service + 包 `R<T>`。业务在 Service |
| 4 | **禁止绕过 `R<T>` 直接返回裸对象** | 前端 `request<T>()` 依赖 `{code,message,data}` 结构解包 |
| 5 | **禁止抛裸 `RuntimeException`** | 统一抛 `BusinessException`，由 `GlobalExceptionHandler` 兜底 |
| 6 | **禁止对 `getupdates` 发起任何额外请求** | iLink 长轮询游标由 Electron 主进程独占，服务端再发一次会**抢走消息**导致桌面端漏收。这是本项目最严重的历史事故 |
| 7 | **禁止在接口里做同步网络探测** | 曾因"绑定状态探测"用 8 秒超时读长轮询，导致每次进办公助理卡 8 秒。接口响应目标 < 500ms |
| 8 | **数据库变更必须走幂等迁移** | 用 `DbMigrationRunner` 或 `db/migration_*.sql`，先查 `information_schema` 再执行 |
| 9 | **禁止对生产库执行 `schema.sql`** | 该文件含 `DROP TABLE IF EXISTS`，只用于本地初始化 |
| 10 | **新增受保护接口必须登记到 `AUTH_PATTERNS`** | `JwtAuthFilter` 用白名单式匹配，漏登记 = 接口裸奔 |
| 11 | **禁止 `@ConfigurationProperties` 与 `@Value` 混用同一前缀** | 自定义配置统一收敛到 `LumenProperties` |
| 12 | **日志禁止打印凭据、完整请求体、token** | 日志会落盘 30 天且体积上限 3GB |
| 13 | **接口必须幂等或明确标注非幂等** | 定时任务、重试、SSE 重连都会重复触发 |

### 分层职责（严格单向依赖）

```
Controller  →  Service  →  Mapper  →  DB
     ↓            ↓
    DTO          Entity
```

| 层 | 允许做 | 禁止做 |
|---|---|---|
| `Controller` | 取 `UserContext`、参数校验注解、调 Service、包 `R.ok()` | 写业务判断、直接用 Mapper（极少数只读例外）、try/catch 业务异常 |
| `Service` | 业务逻辑、事务、抛 `BusinessException`、调用其他 Service | 感知 `HttpServletRequest`、返回 `R<T>`、返回 `ResponseEntity` |
| `Mapper` | 继承 `BaseMapper<T>`，复杂查询用 `LambdaQueryWrapper` | 写业务逻辑 |
| `entity` | 与表结构一一对应，MyBatis-Plus 注解 | 加业务方法、加 `@JsonIgnore` 之外的展示逻辑 |
| `dto` | 请求/响应载体，`@Data` + 校验注解 | 直接被持久化（除非本来就是实体） |

**⚠️ 现有空包**：`browser/`、`common/utils/`、`mcp/`、`plugin/`、`schedule/`、`vo/` 目前**零文件**。新增代码请优先放进已有实际使用的包，不要往空包里塞；若无用应删除。

**⚠️ 孤儿代码**：`config/OpenClawProperties.java`、`service/OpenClawGatewayService.java`、`application.yml` 里的 `openclaw.gateway-url` 已无调用方（链路已迁 iLink Bot），待清理。

## 3. 命名规范

| 对象 | 规则 | 示例 |
|---|---|---|
| 包 | 全小写，单词不缩略 | `com.lumenai.backend.workassistant` |
| 类 | PascalCase | `SessionService`、`JwtAuthFilter` |
| 接口 | 不加 `I` 前缀 | `Tool`（不是 `ITool`） |
| 接口实现 | 语义化命名，不用 `Impl` 后缀 | `DateTimeTool`（不是 `DateTimeToolImpl`） |
| 方法 | camelCase，动词开头 | `listByUser`、`getOrThrow`、`verifyBindingLocally` |
| 常量 | `UPPER_SNAKE_CASE` | `AUTH_PATTERNS`、`DEFAULT_TZ` |
| 数据库表 | 蛇形复数 | `users`、`sessions`、`channel_accounts` |
| 数据库字段 | snake_case | `project_path`、`permission_mode` |
| 配置项 | kebab-case | `max-loop-rounds` |
| DTO | 动词/名词 + `Request` / `Response` | `SessionCreateRequest`、`ScheduleResponse` |

**Controller 方法名 = 动作**：`list` / `create` / `get` / `update` / `delete` / `refresh`。
**Service 查询方法返回值策略**：`getById` 找不到抛异常；`findByXxx` 返回 `null` 或 `Optional`。命名必须让调用方一眼看出会不会抛。

## 4. 接口层（Controller）规范

### 4.1 标准结构

```java
@Tag(name = "会话管理", description = "会话 CRUD 与消息历史")
@RestController
@RequestMapping("/sessions")
@RequiredArgsConstructor
public class SessionController {

    private final SessionService sessionService;

    @Operation(summary = "列出当前用户的会话")
    @GetMapping
    public R<List<SessionResponse>> list() {
        return R.ok(sessionService.listByUser(UserContext.get()));
    }

    @Operation(summary = "创建会话")
    @PostMapping
    public R<SessionResponse> create(@RequestBody(required = false) SessionCreateRequest req) {
        if (req == null) req = new SessionCreateRequest();
        return R.ok(SessionResponse.from(sessionService.create(UserContext.get(), req)));
    }
}
```

要点：

- 类上必须同时有 `@Tag`，方法上必须有 `@Operation(summary=...)` —— Swagger 文档是给别人看的。
- 注入统一用 `@RequiredArgsConstructor` + `private final`（构造器注入），**禁止 `@Autowired` 字段注入**。
- **`context-path = /api` 已在 `application.yml` 配好**，`@RequestMapping` 里**不要**再写 `/api` 前缀。
- 用 `@PatchMapping` 做局部更新，`@PutMapping` 做整体替换。
- 路径参数用 `@PathVariable`，查询参数用 `@RequestParam`，请求体用 `@RequestBody`。

### 4.2 当前用户 ID 的获取

```java
Long userId = UserContext.get();   // ThreadLocal，由 JwtAuthFilter 注入
```

**禁止**从请求体/查询参数里读 `userId` 做鉴权（可被伪造）。`UserContext` 在请求结束时由 filter 清理。

### 4.3 资源归属校验

所有按 ID 操作的接口**必须**校验资源属于当前用户：

```java
// ✅ Service 里校验
public Session getOrThrow(Long userId, Long id) {
    Session s = sessionMapper.selectById(id);
    if (s == null || !s.getUserId().equals(userId)) {
        throw new BusinessException(404, "会话不存在");
    }
    return s;
}
```

**禁止**只按 ID 查询就返回（越权漏洞）。

### 4.4 无 JWT 的内部接口

Electron 主进程直调的接口（`/work-assistant/accounts/confirm`、`/messages/inbound`、`/accounts/session-expired`）走 `noAuth=true` + `ilinkUserId` 反查用户。这类接口：

- **必须**登记在 `JwtAuthFilter.SKIP_PATHS`。
- **必须**在方法注释里写明"为什么可以无认证"以及反查逻辑。
- **禁止**用它们做任何写操作之外的高权限行为。

## 5. 统一响应与异常

### 5.1 `R<T>` 是唯一出口

```java
R.ok()                    // code=200, data=null
R.ok(data)                // code=200
R.fail(400, "参数错误")    // 业务错误
R.fail("服务异常")         // 默认 code=500
```

结构：`{ code, message, data, timestamp }`。**`code == 200` 才代表成功**，前端据此判定。

- **禁止**直接 `return new R<>()` 手搓。
- **禁止**成功时返回 `R.fail` 之外的错误码。
- 需要非 200 的成功语义时（如 201），先团队讨论 —— 当前约定是统一 200。

### 5.2 异常处理

```java
// ✅ 业务异常（会被 GlobalExceptionHandler 转成 R.fail(code, msg)）
throw new BusinessException("邮箱已注册");              // code=400
throw new BusinessException(404, "会话不存在");
throw new BusinessException(401, "Refresh Token 无效或已过期");

// ❌ 禁止
throw new RuntimeException("...");
return R.fail(500, e.getMessage());   // 在 Controller 里手动 catch
```

`GlobalExceptionHandler` 已覆盖：

| 异常 | 返回 |
|---|---|
| `BusinessException` | `R.fail(ex.getCode(), ex.getMessage())`，打 `warn` |
| `MethodArgumentNotValidException` / `BindException` | `R.fail(400, "字段: 消息; ...")` |
| `NoResourceFoundException` | `R.fail(404, "Resource not found: ...")` |
| `Exception` | `R.fail(500, "Internal server error: ...")`，打 `error` + 堆栈 |

**新增异常类型时，必须在 `GlobalExceptionHandler` 里加对应 handler**，否则会落到兜底的 500 分支。

**错误消息面向用户**：写中文、说人话（"邮箱已注册"），不要写技术细节（"Duplicate entry for key 'idx_email'"）。

## 6. 参数校验

用 Jakarta Validation，**在 DTO 上声明，不要在 Service 里手写 if**：

```java
@Data
public class RegisterRequest {
    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;

    @NotBlank(message = "密码不能为空")
    @Size(min = 6, max = 32, message = "密码长度需在 6~32 位之间")
    private String password;
}
```

Controller 上加 `@Valid`：

```java
public R<AuthResponse> register(@Valid @RequestBody RegisterRequest req) { ... }
```

规则：

- **`@NotBlank` 优先于 `@NotNull`**（能挡掉空串）。
- **message 必须是中文**，会原样返回给用户。
- 跨字段校验（如两次密码一致）放 Service，抛 `BusinessException`。
- 嵌套对象校验要加 `@Valid` 级联注解。

## 7. 认证与鉴权

### 7.1 架构

```
请求 → JwtAuthFilter（OncePerRequestFilter）
         ├─ 加 CORS 头 + 放行 OPTIONS
         ├─ path ∈ SKIP_PATHS     → 直接放行
         ├─ path ∉ AUTH_PATTERNS  → 直接放行（公开接口）
         └─ 需要鉴权 → 解析 Bearer Token
                        ├─ 有效 → UserContext.set(userId) → 放行
                        └─ 无效/缺失 → 返回 R.fail(401)
```

### 7.2 ⚠️ 新增受保护接口必须登记

`JwtAuthFilter` 是**白名单式**的，只有匹配 `AUTH_PATTERNS` 前缀的路径才校验 Token。**新增一个需要登录的接口路径时，必须同时把前缀加进 `AUTH_PATTERNS`**，否则接口会完全裸奔。

```java
private static final Set<String> AUTH_PATTERNS = Set.of(
        "/api/auth/me", "/api/sessions", "/api/chat", "/api/tools",
        "/api/schedules", "/api/schedule-runs", "/api/files", "/api/profile",
        "/api/work-assistant/accounts", "/api/work-assistant/messages",
        "/api/work-assistant/sessions", "/api/work-assistant/reply/stream"
);
```

注意 `AUTH_PATTERNS` 用的是 `startsWith` 前缀匹配，所以路径设计要让前缀能覆盖整个资源：

- ✅ `/api/work-assistant/accounts`、`/api/work-assistant/accounts/{id}`
- ⚠️ 若新增 `/api/work-assistant/settings`，需追加 `/api/work-assistant/settings`

### 7.3 JWT 约定

`JwtUtil` 提供的方法：

| 方法 | 用途 |
|---|---|
| `generate(userId, email, username)` | 签发 Access Token |
| `generateRefresh(userId, email, username)` | 签发 Refresh Token |
| `validate(token)` | 校验签名与有效期 |
| `isRefreshToken(token)` | 区分 Access / Refresh |
| `parseUserId(token)` | 从 Token 取 userId |
| `extractToken(header)` | 从 `Authorization` 头剥离 `Bearer ` 前缀 |

- 有效期：Access 2 小时、Refresh 7 天。
- Header 固定 `Authorization: Bearer <token>`。
- **Token 里不放敏感信息**（密码、手机号等）。
- 密钥走 `${JWT_SECRET:...}`，生产必须用至少 32 字节随机串。

### 7.4 已知不一致（待修）

`JwtAuthFilter` 里硬编码了 `Access-Control-Allow-Origin: *`，而 `WebMvcConfig` 用的是 `lumen.cors.allowed-origins` 白名单 + `allowCredentials(true)`。浏览器规范下 `*` 与 credentials 不能共存，二者实际由 filter 的表头生效。**新增跨域需求时应统一到 `LumenProperties`，不要继续加硬编码。**

## 8. Service 层规范

### 8.1 类结构

```java
@Service
@RequiredArgsConstructor
public class SessionService {

    private final SessionMapper sessionMapper;
    private final MessageMapper messageMapper;

    public List<SessionResponse> listByUser(Long userId) { ... }
    public Session getOrThrow(Long userId, Long id) { ... }
}
```

- 用 `@RequiredArgsConstructor` + `private final` 构造器注入。
- 类和方法加中文 Javadoc，说明**业务语义**而非重复方法名。
- Service 返回**实体或 DTO**，**不返回** `R<T>`。

### 8.2 ⚠️ 禁止同步网络探测

**任何接口路径上都不允许出现"探测式"的同步 HTTP 调用。** 历史事故：办公助理的绑定状态查询调用了 iLink 长轮询探测，token 有效时服务端挂住连接，导致每次进页面卡满 8 秒超时。

正确做法：

```java
// ✅ 只读库，零网络调用
public boolean verifyBindingLocally(String channel, Long userId) { ... }

// ❌ 探测式网络调用
public boolean verifyBinding(String channel) {
    return ilinkBotClient.probeSession(...);   // 可能挂 8 秒
}
```

判定标准：接口 P99 应 < 500ms。若某操作天然慢（LLM 生成、大文件），必须走 SSE 流式或异步任务，不能阻塞 HTTP 响应。

### 8.3 事务

- 写操作加 `@Transactional(rollbackFor = Exception.class)`。
- **禁止**在事务方法里做网络调用（LLM、HTTP），会长时间占着数据库连接。
- 事务方法**禁止**是 `private`（Spring AOP 代理不生效）。
- 自调用（同类内部方法互调）不走代理，事务会失效 —— 需要时抽到另一个 Bean。

### 8.4 幂等

定时任务、外部回调、SSE 重连都可能重复触发。写操作前必须判断是否已处理：

```java
ChannelMessage exist = messageMapper.selectOne(
        new LambdaQueryWrapper<ChannelMessage>()
                .eq(ChannelMessage::getIlinkMsgId, ilinkMsgId));
if (exist != null) return exist;   // 幂等返回
```

## 9. 持久层规范（MyBatis-Plus）

### 9.1 实体

```java
@Data
@TableName("sessions")
public class Session {

    @TableId(type = IdType.AUTO)
    private Long id;

    /** 归属用户，所有查询必须带上 */
    @TableField("user_id")
    private Long userId;

    @TableField("project_path")
    private String projectPath;

    @TableField("created_at")
    private LocalDateTime createdAt;
    @TableField("updated_at")
    private LocalDateTime updatedAt;
}
```

- 全项目**零 Mapper XML**（`resources` 下没有 `mapper/*.xml`，`mapper-locations` 配置留着只是兜底）。
- 字段用 `@TableField` 显式映射，**不要依赖驼峰自动转换**（虽然 `map-underscore-to-camel-case: true` 已开，显式更安全）。
- 主键统一 `@TableId(type = IdType.AUTO)`，数据库 `BIGINT AUTO_INCREMENT`。
- 时间字段用 `LocalDateTime`，不用 `Date` / `Timestamp`。
- 类注释写清对应表名。
- 不使用 Lombok `@EqualsAndHashCode`/`@ToString` 于实体上（避免懒加载陷阱），`@Data` 足够。

### 9.2 查询

```java
// ✅ 参数化 + 类型安全
sessionMapper.selectList(new LambdaQueryWrapper<Session>()
        .eq(Session::getUserId, userId)
        .eq(Session::getStatus, "active")
        .orderByDesc(Session::getUpdatedAt));

// ❌ 字符串拼接、SQL 注入风险
sessionMapper.selectList(new QueryWrapper<Session>().apply("user_id = " + userId));
```

**铁律：所有按用户维度的查询必须带 `user_id` 条件**（防止越权）。

### 9.3 逻辑删除（⚠️ 配置已开，但当前实际未启用）

`application.yml` 里声明了全局逻辑删除：

```yaml
mybatis-plus.global-config.db-config:
  logic-delete-field: deleted
  logic-delete-value: 1
  logic-not-delete-value: 0
```

**但这是一项"空配置"**：核对确认，`schema.sql` / `db/*.sql` 中**没有任何表带 `deleted` 列**，`entity/` 下 10 个实体也**没有一个声明该字段**。也就是说当前的删除操作全是物理删除，上述配置没有生效。

因此：

- **现状**：`mapper.deleteById(id)` 是**真删**，删了就没了。做数据恢复相关功能时不要假设有软删除。
- **新增表时**：若业务需要软删除，必须**同时**做两件事 —— 表里加 `deleted TINYINT(1) NOT NULL DEFAULT 0`，实体里加 `@TableLogic private Integer deleted;`。只加表字段不生效，只加注解会报 Unknown column。
- **写查询时**：不要依赖框架自动过滤 `deleted`，当前所有查询都是全量。
- 建议择机统一决策：要么给所有表补齐软删除，要么把这段配置删掉避免误导。

### 9.4 分页（⚠️ 拦截器已注册，但当前零使用）

`MyBatisPlusConfig` 已注册 `PaginationInnerInterceptor(DbType.MYSQL)`，但**核对确认当前没有任何代码使用分页**（无 `selectPage` / `new Page<>` 调用）。列表接口目前都是 `selectList` 全量返回。

新增列表接口时的规则：

```java
Page<ScheduleRun> page = scheduleRunMapper.selectPage(
        new Page<>(pageNum, pageSize),
        new LambdaQueryWrapper<ScheduleRun>()
                .eq(ScheduleRun::getUserId, userId)
                .orderByDesc(ScheduleRun::getCreatedAt));
```

- **`pageSize` 必须有上限**（建议 ≤ 100），禁止让前端传任意大值。
- 数据量可能增长的列表接口**必须分页**，禁止无限制 `selectList`。
- 分页参数用 `pageNum` / `pageSize`，响应统一返回 `total` / `records`。

## 10. 数据库变更规范

### 10.1 两条路径

| 场景 | 做法 |
|---|---|
| 本地从零初始化 | 改 `resources/db/schema.sql`（⚠️ 含 `DROP TABLE`，**只能本地跑**） |
| 已有环境的增量变更 | 写 `resources/db/migration_*.sql`，并在 `DbMigrationRunner` 里注册 |

### 10.2 `DbMigrationRunner` 规范

启动时执行，**必须幂等**。标准范式：

```java
private void addColumnIfNotExists(String table, String column, String definition, String after) {
    try {
        Integer count = jdbcTemplate.queryForObject(
                "SELECT COUNT(*) FROM information_schema.COLUMNS " +
                        "WHERE TABLE_SCHEMA = DATABASE() AND TABLE_NAME = ? AND COLUMN_NAME = ?",
                Integer.class, table, column);
        if (count != null && count > 0) {
            log.debug("{}.{} 已存在，跳过迁移", table, column);
            return;
        }
        jdbcTemplate.execute("ALTER TABLE " + table + " ADD COLUMN " + column + " " + definition
                + (after != null ? " AFTER " + after : ""));
        log.info("迁移完成：{}.{} 字段已添加", table, column);
    } catch (Exception e) {
        log.warn("{}.{} 迁移失败（可能已存在）: {}", table, column, e.getMessage());
    }
}
```

规则：

- **先查 `information_schema` 再执行**，绝不无脑 `ALTER`。
- **失败只 `warn` 不中断启动**（迁移失败不应导致服务起不来）。
- 类上加 `@Order(1)` 保证在其他 `CommandLineRunner` 之前执行。
- 新增字段要**给默认值**（`NOT NULL DEFAULT x`）或允许 `NULL`，避免存量行报错。
- **大表加字段要评估锁表时间**，必要时用 `pt-online-schema-change`。

### 10.3 字段设计约定

- 字符集 `utf8mb4` / `utf8mb4_unicode_ci`。
- 主键 `BIGINT AUTO_INCREMENT`。
- 时间 `DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`，更新时间戳用 `ON UPDATE CURRENT_TIMESTAMP`。
- 状态/枚举字段用 `VARCHAR(16~32)` 存字符串（不用魔法数字），并在 `COMMENT` 里列出全部取值。
- 建索引：外键、高频查询条件、排序字段。

## 12. Agent / Tool 扩展规范

### 12.1 新增一个工具

工具类**必须同时实现 `Tool` 接口 + 标注 Spring AI `@Tool` 注解**，`ToolRegistry` 用一个 `List<Tool>` 收集全部。

```java
@Slf4j
@Component
public class MyTool implements Tool {

    @Override public String name() { return "MyTool"; }
    @Override public String description() { return "Use when ... (英文，LLM 依据此描述决定是否调用)"; }
    @Override public Permission requiredPermission() { return Permission.ASK_USER; }
    @Override public boolean isReadOnly() { return true; }

    @Override
    public Map<String, Object> parameterSchema() {
        // JSON Schema
        Map<String, Object> props = new HashMap<>();
        props.put("path", Map.of("type", "string", "description", "..."));
        return Map.of("type", "object", "properties", props, "required", List.of("path"));
    }

    @org.springframework.ai.tool.annotation.Tool(name = "MyTool", description = "...")
    public String execute(
            @ToolParam(description = "...") String path) {
        // 实际实现
    }

    @Override
    public ToolResult execute(ToolContext ctx, Map<String, Object> args) {
        long start = System.currentTimeMillis();
        String out = execute((String) args.get("path"));
        return ToolResult.ok(out, (int) (System.currentTimeMillis() - start));
    }
}
```

要点：

- `name()` 与 `@Tool(name=...)` **必须一致**。
- `description()` 与 `@Tool(description=...)` **必须一致**（前者给旧链路，后者给 Spring AI）。
- **`description()` 用英文写**，是给 LLM 看的，要写清"什么时候用我"。
- `parameterSchema()` 与 `@ToolParam` 描述**必须一致**。
- 必须返回 `ToolResult`，**禁止抛异常穿透**（失败用 `ToolResult.fail(msg, ms)`）。
- `isReadOnly() = true` 的工具可被并行执行，判定标准是"无副作用"。
- 工具里**不要自己弹框问用户**，需要交互时用 `AskUserQuestionTool`。

### 12.2 权限档位

`Tool.Permission` 三档与数据库 `permissions` 表对应：

| 枚举 | 语义 | 数据库 `default_mode` |
|---|---|---|
| `AUTO_ALLOW` | 直接执行，不问 | `auto_allow` |
| `ASK_USER` | 按用户全局模式决定（`manual` 弹框 / `smart` 自动批准 / `fully` 全放行） | `ask_user` |
| `DENY` | 永远拒绝 | `deny` |

新增工具**必须**在 `db/schema.sql` 的 `permissions` 初始化 `INSERT` 语句里追加一行（当前 15 个工具，与 `tool/` 下的实现一一对应）：

```sql
INSERT INTO permissions (tool_name, default_mode) VALUES
  ('Read',         'auto_allow'),
  ('Write',        'ask_user'),
  ('Delete',       'ask_user'),
  ('Shell',        'ask_user'),
  ...
```

判定原则：**只读、无副作用 → `auto_allow`**；**有写入/执行/外发 → `ask_user`**。`deny` 目前没有内置工具使用。

### 12.3 Tool 上下文

```java
record ToolContext(Long sessionId, String projectPath, Map<String, Object> metadata) {}
```

工具执行需要用户身份时，从 `UserContext.get()` 取（ThreadLocal）。

### 12.4 工具目录归属

| 目录 | 放什么 |
|---|---|
| `tool/filesystem/` | Read / Write / Edit / Delete / Glob / Grep |
| `tool/shell/` | Shell |
| `tool/code/` | Exec |
| `tool/web/` | WebSearch / WebFetch |

## 13. SSE 流式事件契约（前后端强耦合，改动需双方同步）

聊天接口：`POST /api/chat/stream`，`produces = text/event-stream`。

| event | data | 说明 |
|---|---|---|
| `reasoning` | `{"text": "..."}` | 深度思考增量 |
| `text` | `{"text": "..."}` | 正文增量 |
| `tool_call_start` | 工具名 + 入参 | 工具开始执行 |
| `tool_call_end` | 工具名 + 结果 + 耗时 | 工具执行结束 |
| `permission_request` | 工具名 + 入参 | 需要用户授权，前端弹框 |
| `tool_blocked` | 工具名 + 原因 | 被权限策略拒绝 |
| `question` | 问题 + 选项 | Agent 反问用户 |
| `compress_start` / `compress_end` | — | 上下文压缩边界 |
| `error` | `{"message": "..."}` | 错误 |
| `done` | `{"finalContent": "..."}` | 结束，携带完整回复 |

规则：

- `done` 事件的 `finalContent` 是**落库依据**，由 `ChatController` 写入 `messages` 表。
- **新增事件类型必须同步前端**（`api/session.ts` 的 `StreamCallbacks`），否则前端会静默忽略。
- **改动已有事件的 data 结构属于破坏性变更**，必须同版本发布前后端。
- 每个 event 都必须能被前端安全忽略 —— 即前端遇到未知 event 不能崩。

## 14. 日志规范

用 `@Slf4j` + 占位符（**禁止字符串拼接**）：

```java
// ✅
log.info("创建会话: userId={}, sessionId={}", userId, sessionId);
log.warn("Business error: code={}, msg={}", ex.getCode(), ex.getMessage());
log.error("Unexpected error", ex);   // 异常对象放最后一个参数

// ❌
log.info("创建会话: userId=" + userId);
```

| 级别 | 用途 |
|---|---|
| `error` | 需要人工介入的异常，**必须带堆栈** |
| `warn` | 业务异常、降级、可恢复失败 |
| `info` | 关键状态变更（登录、创建会话、迁移完成、工具注册） |
| `debug` | 排查用细节（跳过的迁移、参数内容） |

**禁止**：

- 打印密码、Token、API Key、完整请求体。
- 在循环里打 `info`（性能与磁盘）。
- 把大文件内容、完整 LLM prompt/response 打进 `info`。

配置现状：`com.lumenai.backend` = DEBUG，`org.springframework.ai` = DEBUG；日志文件 `logs/lumen-ai.log`，单文件 100MB、保留 30 天、总量上限 3GB。

⚠️ Boot 4 的滚动策略配置路径是 `logging.logback.rollingpolicy.*`（**不是** `logging.file.*`）。

```
perf(work-assistant): 绑定状态查询改为纯 DB 读取，删除 iLink 长轮询探测

- GET /work-assistant/accounts/{channel} 不再调用 probeSession。iLink 的

  造成桌面端漏收消息。
```

### 16.2 Windows 环境必须走 `-F` 文件

本机 `[Console]::OutputEncoding` 是 GBK，`git commit -m "中文"` 会把参数按 GBK 编码传给 git，**提交信息真会坏**（不是显示问题）。

```powershell
$enc = New-Object System.Text.UTF8Encoding $false
[System.IO.File]::WriteAllText("$ws\_msg.txt", $content, $enc)
git commit -F "$ws\_msg.txt"
```

git **输出**的中文乱码只是控制台解码问题，仓库里是合法 UTF-8。

### 16.3 常见 git 坑

- 中文文件名会被转义成 `\346\234\215...`，必须加 `-c core.quotepath=false`。
- **提交后必须回读** `git log --oneline`、`git ls-tree -r <sha>` 确认真实内容，不要相信 push 回显。
- 环境存在"自动暂存"行为：指定文件提交后，`.idea/vcs.xml` 等可能被顺带暂存成 `A`，提交完 `git restore --staged` 复核。
- **彻底移除已推送的敏感文件必须重写历史**（`git rm --cached` → `commit --amend` → `push --force-with-lease`），普通提交只是删工作区副本，历史里仍在。
